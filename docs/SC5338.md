## 1. 器件身份与规格

### 1.1 现场实测（S4602 原厂日志 + 原厂 DTB）

| 字段 | 值 | 来源 |
|---|---|---|
| 型号 | SmartSens **SC5338** | `compatible = "smartsens,sc5338"`（原厂 DTB） |
| Chip ID | `0xce50`（`0x3107=0xce`, `0x3108=0x50`） | `Detected SC00ce50 sensor`；公开驱动 `SC5338_CHIP_ID_H/L` |
| I2C | `i2c1@ff510000`, addr `0x30` | DTB `/i2c@ff510000/sc5338@30`，dmesg `1-0030` |
| 有效分辨率 | **2880 × 1620**（4.67 MP，模组标称 4 MP） | `set format 2880x1620`；公开驱动 `SENSOR_MAX_WIDTH/HEIGHT` |
| 数据格式 | RAW10 / Bayer | Ingenic 驱动 `TX_SENSOR_RAW10`、`mipi_sc.data_type_value = RAW10` |
| MIPI | CSI-2 **2 lane**（`data-lanes = <1 2>`） | DTB endpoint；`supported_modes not set lane_num(2)` |
| 帧率 / 模式 | 30 fps linear；15 fps WDR 2-frame (DOL) | 公开驱动文件头注释；`sc5338_mipi` / `sc5338_mipi_dol` |
| 原厂启动模式 | `hdr: 5` = **HDR_X2** | `rk-camera-module.h`：`NO_HDR=0, HDR_X2=5, HDR_X3=6` |
| 模组 / 镜头 | `CMK-OT1607-FV1` / `M12-40IRC-4MP-F16` | DTB `rockchip,camera-module-name/lens-name` |
| 电源 | AVDD 3.3 V (`vcc33sys`)、DOVDD 1.8 V (`vcc-1v8`)、DVDD 1.2 V (`vcc-dvdd`) | DTB `*-supply` + regulator 节点 |
| GPIO | `pwdn = gpio1 28`、`reset = gpio1 29`（flags 0） | DTB `pwdn-gpios`/`reset-gpios`（phandle 81 = `gpio1@ff620000`） |
| 时钟 | `clocks = <&cru 103>`, `clock-names = "xvclk"`；板载 24 MHz 晶振 | DTB；`103` 是 CRU clock specifier，不是 phandle |
| 原厂驱动版本 | `00.01.01`（同板 `sc530ai 00.01.01`、`sc401ai 00.01.05`） | dmesg `driver version` |

> **注意**：旧笔记「400 万像素 / 2K」是模组标称口径；实际输出 2880×1620。
> **注意**：SmartSens 公开型号 **SC5338P**（DSI-2 Pro，5 MP，2888×1628，≈2024 年，
> OpenIPC 传感器目录有规格页）与本机 SC5338 **是否同一颗 die 未证实**。
> 一切以 `0xce50` 与寄存器表为准，不要按 SC5338P 的 datasheet 改寄存器。

### 1.2 官方/第三方规格参考（仅作背景，不作为寄存器依据）

- SmartSens 官方 AI/SL/IoT 产品线：`SC5338P 5MP 1/2.7" 2.0 µm 2888H×1628V 30fps MIPI CSP41`（smartsenstech.com）
- OpenIPC 传感器库：`https://openipc.org/cameras/sensors/sc5338p`（4.7 MP、1/2.7″、2 µm、30 fps、MIPI CSI-2）
- 思特威选型表：SC5336P / SC5338P 均为 2888×1628、2.0 µm、1/2.7″

## 2. 现场 dmesg 证据

原文与完整去重事件见 [`sc5338-dmesg.txt`](evidence/sc5338-dmesg.txt)，关键行（原厂正常启动日志）：

```text
[    0.357534] sc401ai 1-0030-2: Unexpected sensor id(00ce50), ret(0)
[    0.366700] sc530ai 1-0030-1: Unexpected sensor id(00ce50), ret(0)
[    0.367576] sc5338 1-0030: driver version: 00.01.01
[    0.368366] sc5338 1-0030: supported_modes not set lane_num(2)
[    0.375000] sc5338 1-0030: Detected SC00ce50 sensor
[    0.375078] rockchip-mipi-dphy-rx ff4b0000.csi-dphy: match m01_f_sc5338 1-0030:bus type 4
[    5.846908] sc5338 1-0030: set format 2880x1620, hdr: 5
[    6.025419] sc5338 1-0030: start stream 2880x1620, hdr: 5
[    6.02....] rkcif_mipi_lvds: stream[0] / stream[1] start streaming
```

要点：

1. **三个驱动共址 0x30**：原厂 DTB 在 `i2c1` 下同时挂了 `sc401ai@30`、`sc530ai@30`、
   `sc5338@30`。内核依次 probe，前两个读到 `0xce50` 与自身 ID 不符就退出，只有 `sc5338` 匹配。
   移植时**只保留 sc5338 节点**，否则同址冲突会复现。
2. `hdr: 5` 不是「HDR 等级 5」，而是 `enum rkmodule_hdr_mode { NO_HDR=0, HDR_X2=5, HDR_X3=6 }`
   —— 两帧 HDR（DOL / virtual channel）。
3. `m01_f_sc5338` 是 DPHY 匹配用的模组名（与 DTB `camera-module-name` 不同，别混淆）。
4. 两份日志共 8 次启动、7 次成功 `start stream`，说明该寄存器序列在板上是稳定跑通过的。

## 5. 寄存器表交叉验证（决定性结论）

报告：[`sc5338-regs-crosscheck.txt`](evidence/sc5338-regs-crosscheck.txt)，
可复现工具：`tools/verify_sc5338_regs.py`。

vmlinux 里共 **9 张** SmartSens 风格初始化表（4 B/项 `struct regval {u16 addr; u8 val; u8 pad}`），
其中 `sc5338_set_ctrl` 符号（`@0x85665c`）之后的 3 张属于 sc5338：

| 原厂表偏移 | 项数 | 与公开 linear 相似度 | 与公开 HDR2 相似度 | 第 5 项 `0x301f` |
|---|---|---|---|---|
| `0x856938` | 200 | 0.8160 | 0.7979 | `0x1a` |
| `0x856c5c` | 196 | 0.8571 | 0.8329 | `0x04` |
| **`0x856f70`** | **198** | 0.9062 | **0.9551** | **`0x0b`（公开 HDR2 也是 0x0b）** |

最接近的原厂表与公开 HDR2 表的差异**只有 2 处插入**：
多 `{0x0100, 0x00}`（软 standby）1 项，以及 16 项 `0x3213 / 0x3200…0x320f` 系列配置。
即 **公开表是原厂表的近似子集，同源**。

导出成品：[`src/sensor-reference/sc5338-regs-rockchip.h`](../src/sensor-reference/sc5338-regs-rockchip.h)
（996 行），含 5 组 `struct regval` 数组：

- `sc5338_vendor_mode1/2/3_*_regs` — **原厂 vmlinux 解析，优先使用**，各带偏移/相似度注释
- `sc5338_public_linear_*` / `sc5338_public_hdr2_*` — 公开驱动对照

限制：交叉验证只覆盖 **mode 初始化表**；曝光/增益/VC/HDR 控制逻辑、3 张表各自对应哪个 mode
（尤其 `0x301f = 0x1a / 0x04` 是什么模式）**尚未实板确认**，需按第 7 节验收流程定夺。

## 6. 移植到 OpenIPC 的改动清单（P1，**代码已编写并接入 CI**）

> **状态（2026-11-11）**：驱动源码已完成并接入 GitHub Actions 构建。
> - `src/kernel-patches/sc5338.c` —— 基于 OpenIPC `sc500ai.c` 骨架改写，SC5338 专属控制逻辑（chip id `0xce50`、2-lane、2880×1620、linear/HDR_X2）。
> - `src/kernel-patches/sc5338-tables.h` —— 由 `tools/gen_sc5338_tables.py` 从参考头 `sc5338-regs-rockchip.h` 提取的**仅 2 张表**（linear + vendor_mode3/HDR_X2），避免未使用数组的编译告警。
> - `tools/apply_kernel_patch.py` —— CI 在 `make` 前把上述两文件拷入 `linux/drivers/media/i2c/` 并向 `Makefile`/`Kconfig` 注入 `VIDEO_SC5338`。
> - `board/s4602/s4602_kernel_fragment.config` 加 `CONFIG_VIDEO_SC5338=y`。
> - `.github/workflows/build.yml` 加「Inject SC5338 sensor driver」步骤。
> **编译期闭环已完成**；实板 i2c 绑定、出流、IQ/3A tuning 仍为后续验收项（见第 7、8 节）。

1. `cp drivers/media/i2c/sc500ai.c → sc5338.c`，全局改名；保留 GPL 头与上游版权。
2. 宏改为：`SC5338_CHIP_ID 0xce50`、`REG_CHIP_ID_H/L = 0x3107/0x3108`、
   `LANES = 2`、`XVCLK` 与 link freq 按 DTB/原厂实测定（见风险）、mode 表 2880×1620 + HDR_X2。
3. 把 `sc5338-regs-rockchip.h` 的 `vendor_mode3`（`0x856f70`，与公开 HDR2 相似度 0.9551）
   作为 HDR 模式 `reg_list`，另选一张作为 linear；`{SC5338_REG_NULL,0}` 对齐 sc500ai 的 `REG_NULL`。
4. 实现 `RKMODULE_GET_HDR_CFG` / `RKMODULE_SET_HDR_CFG`（`HDR_NORMAL_VC`、
   `hdr_mode = HDR_X2`）、V4L2 曝光/增益 controls 用 `0x3e00…0x3e13`。
5. `Kconfig` 加 `config VIDEO_SC5338`，`Makefile` 加
   `obj-$(CONFIG_VIDEO_SC5338) += sc5338.o` —— 这两项由 `tools/apply_kernel_patch.py`
   在 CI 克隆 `OpenIPC/linux` 后、`make` 前自动注入（不直接改 linux 树，保持可复现）。
   `CONFIG_VIDEO_SC5338=y` 写进 `board/s4602/s4602_kernel_fragment.config`，
   经 `merge_config.sh` 叠加进内核（原厂 `rv1126.generic.config` 基线不动）。
6. 板级 DTS：沿用第 3.1 节节点；**删除/禁用 `sc530ai@30` 与 `sc401ai@30`**；
   保留 `csi-dphy` / `rkcif_mipi_lvds` / `rkisp-vir0` 链路节点（原厂 DTB 已是完整拓扑）。
7. 确认 `CONFIG_CMDLINE_FORCE=y` + slot 对应 `ubi.mtd`（[`BOOT_FEASIBILITY.md`](BOOT_FEASIBILITY.md)），
   构建 FIT 并 `iminfo` 验证后再写入。
8. **IQ / 3A**：Rockchip rkaiq 需要 sensor 对应的 tuning XML（类似
   `sc5338_CMK-OT1607-FV1_M12-40IRC-4MP-F16.xml`）。原厂 `system_a.img` 是
   squashfs-in-UBI，尚未解包，**这是目前唯一还没拿到的资料**；同时需确认 OpenIPC rootfs
   是否带 rkaiq/rockit 用户态库。

```text

→ dmesg "Detected SC00ce50 sensor"
```

## 7. 风险与未证项

| # | 项 | 影响 | 处理 |
|---|---|---|---|
| 1 | **未实板验证**；设备仍半砖 | 所有资料只是纸面闭环 | 先救砖 → 恢复原厂 → 全片备份，红线不变 |
| 2 | 原厂 3 张表的 mode 归属未确认 | 可能选错 linear/HDR 表 | 实板上用 `0x301f` 值 + 抓流帧率/VC 判定 |
| 3 | xvclk 频率 | DTB `clocks = <&cru 103>` 未解析到具体时钟名；板载 24 MHz；sc500ai 用 24 MHz、sc401ai 用 27 MHz | 构建前查 CRU 绑定 / 示波器量 |
| 4 | MIPI link freq | 公开驱动 `clk = 864` 单位需换算；sc500ai 用 198/405 MHz | 对照原厂寄存器表 `0x320c/0x320d` HTS 与 VTS 反推 |
| 5 | AVDD 3.3 V vs SmartSens 规格 2.8 V | 板级设计与 datasheet 不一致 | 以原厂 DTB/regulator 为准，不按 SC5338P datasheet 改 |
| 6 | SC5338 vs SC5338P | 型号后缀不同、die 关系未证 | 只认 `0xce50` 与寄存器表 |
| 7 | IQ/3A tuning 文件缺失 | 能出 RAW 但 3A/画质不正常 | 解包原厂 rootfs 的 UBI/squashfs 找 XML |
| 8 | GPL-2.0 | 移植公开驱动需保留版权头 | 保留文件头、注明来源与改动 |
| 9 | BSP 版本差异 | OpenIPC 与原厂同为 4.19.111，但 rkcif/rkisp 子树可能有补丁差异 | 编译期核对 `rk-camera-module.h`、结构体定义 |
